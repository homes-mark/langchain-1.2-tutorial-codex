01术语速查：理解职责比记缩写重要

中文 / 英文本教程中的含义不要混淆
消息 / Message带角色与元数据的模型上下文单位不只是字符串
提示模板 / Prompt Template把变量组织成文本或聊天消息本身不调用模型
链 / Chain按既定连接执行的处理流程概念不等于旧 LLMChain 类
Runnable / LCEL可组合调用接口与表达方式组合不能消除类型契约
结构化输出 / Structured Output满足字段契约的模型结果结构正确不等于事实正确
工具调用 / Tool Calling模型提出工具名与参数，应用执行绑定不等于执行
智能体 / Agent模型结合工具结果迭代选择下一步循环需要预算与边界
记忆 / Memory短期线程状态或跨线程长期信息checkpointer 与 store 职责不同
向量表示 / Embedding把内容映射为可比较的数值向量相似度不是事实证据
检索器 / Retriever根据问题返回候选文档候选需检查权限与相关性
检索增强生成 / RAG检索资料后基于证据生成回答不自动消除幻觉
人在回路 / HITL在明确动作之前暂停，接受人工决定应批准具体参数
幂等 / Idempotency同一请求重复到达时避免重复副作用不是简单捕获异常

06HANDOFF.md 的组织方式

HANDOFF.md 是给下一次会话的工作上下文，不是只有待办项的摘要。接手者应先读它，再根据其中标明的文件和命令继续，无须重新查找本次聊天记录。

部分必须保存的信息
任务与范围用户要求、中文/Python 1.2 基线、22页交付与离线目标
已完成完成的页面、示例、五阶段项目、导航进度与交付文件
进行中与待解决尚未完成的具体事项、阻塞原因；无事项时明确写无
关键决策固定版本、静态构建、离线固定模型与在线分支、项目安全边界
目录与入口工作目录、首页、内容源、构建脚本、测试脚本和报告路径
验证记录命令、解释器、日期、实际结果；区分通过、未执行与受限
已知限制真实模型未测部分、教学检索限制、持久化与部署边界
下一步计划按优先级列出可以直接执行的动作与完成判据

每次切换会话前更新状态和验证结果。不要保存 API 密钥、访问令牌或真实员工数据；只记录凭据应如何由环境提供。若代码已改变而报告还是旧的，应在交接中明确标记需要重跑，不能继续声称全部通过。

07完成课程后的知识自测

  1. 模型对象为什么不等于会话记忆？提示模板的输出是什么类型？
  2. 固定链与 Agent 的控制流程有什么不同？什么时候固定链更合适？
  3. bind_tools 是否执行工具？为什么 ToolMessage 必须对应调用 ID？
  4. Pydantic 校验通过为什么仍可能产生错误业务结果？
  5. checkpointer 与 store 分别解决什么问题？线程 ID 为什么不能代替鉴权？
  6. RAG 没检索到资料时应该如何处理？文档中的恶意指令为什么不能变成权限？
  7. 人工批准后网络重试，如何保证没有重复创建工单？
  8. pip check 通过为什么仍需要实际导入与 invoke？
参考答案与复习入口

1：模型调用需要显式上下文；模板生成 PromptValue，见02–03。2：链的路线由程序预先指定，Agent 根据状态选择动作，见04、07。3：绑定只提供定义，执行由应用完成，ID 用于配对，见06。4：结构约束不验证来源事实或权限，见05。5：前者保存线程状态，后者保存跨线程信息；身份仍需可信鉴权，见08、11。6：拒绝编造并说明证据不足，资料只作数据，见09–11、14。7：批准明确参数，写入使用持久化幂等约束和事务，见19。8：元数据约束不能覆盖运行时符号兼容，见20。

实践验收：从阶段一运行到阶段五，说明每阶段新增了哪一项能力；展示一次拒绝写入、一次批准写入与重复请求不重复建单的回归结果。最后导出学习进度，并能向另一位开发者解释 HANDOFF 中哪些验证尚未覆盖真实生产环境。
