20 · 迁移与排错：读懂新旧代码的边界

把旧版教程中的 Chain、Memory 和 Agent 写法映射到 1.2 路径，用实际导入与执行定位依赖问题。

01先判断旧代码属于哪一代

迁移前先记录旧环境、旧代码的真实输入输出和测试样本。不要同时改模型、提示、检索器与依赖版本，否则出现行为变化时很难定位原因。此教程面向 Python LangChain 1.2，使用固定的 1.2.0 基线；网上标着“LangChain 教程”的内容可能来自完全不同的版本。

旧写法或概念本教程路径迁移时检查什么
LLMChain、ConversationChain用 Runnable / LCEL 表达固定流程返回字典还是字符串、历史如何传入
ConversationBufferMemory显式消息历史，或 Agent state + checkpointer线程隔离、持久化和上下文预算
langgraph.prebuilt.create_react_agentlangchain.agents.create_agentsystem_prompt、middleware、输入状态
旧 AgentExecutor 手工组合优先使用 create_agent工具、停止条件、回传键与异常路径
from langchain.prompts import ...from langchain_core.prompts import ...实际安装包与模块路径
各提供商旧的集中导入对应集成包，如 langchain_openai集成包必须单独安装并锁版本

这是概念与用法迁移，不是机械替换类名。旧功能的一部分位于 langchain-classic；它可以服务于旧项目维护，但不属于本教程基线依赖。不要为了让一行旧 import 暂时成功，就把不同年代的示例混在同一个新项目里。

02迁移不能只看 import 是否成功

旧链可能返回带有 output 字段的字典，本教程的 prompt | model | StrOutputParser() 返回字符串。Agent 的 invoke 返回状态，最终文本通常从 messages 的末条消息读取；结构化结果则按所用策略从 structured_response 读取。接口类型变了，下游代码也要跟着检查。

记忆迁移尤其不能只换构造函数。短期记忆关联线程历史，长期记忆关联跨线程存储；两者都不等于把整个聊天塞回提示。原先全局共享的 Memory 还可能造成用户数据串线。迁移后至少验证两个不同线程、两名不同用户以及进程重启后的行为。

create_react_agent 的旧 prompt 参数不能无条件照搬到新接口；固定系统提示使用 system_prompt，动态提示与模型前后处理使用相应 middleware。传入 create_agent 的模型也不应先随意 bind_tools 再期待所有结构化输出策略正常工作。先采用本教程已运行的最小例子，再逐项恢复业务功能。

03按四层顺序排错

  1. 解释器：确认终端使用了预期虚拟环境。优先使用 python -m pip，避免 pip 与 python 指向不同安装。
  2. 依赖：打印实际版本，而不是只看 requirements 文件。文件描述计划，已安装环境才决定执行结果。
  3. 导入：确认模块属于 core、提供商集成、LangGraph 还是旧 classic 包。检查项目中是否有 langchain.py、openai.py 等同名文件遮蔽包。
  4. 最小执行：导入后真正创建 Agent 并 invoke 一次，接着运行工具、记忆、检索的独立检查。最后再回到完整项目。

执行 python examples/01_check_environment.py，它同时检查精确版本、真实导入与一次 Agent 图调用。脚本无密钥、不联网，完整依赖由锁文件固定。

"""Dependency and real import check. Run: python examples/01_check_environment.py"""
from importlib.metadata import version
from langchain.agents import create_agent
from langchain_core.messages import AIMessage
from common import ScriptedChatModel

EXPECTED = {"langchain": "1.2.0", "langchain-core": "1.2.5", "langgraph": "1.0.5",
            "langgraph-prebuilt": "1.0.5", "langchain-openai": "1.1.6",
            "langchain-text-splitters": "1.1.0"}
for name, expected in EXPECTED.items():
    actual = version(name)
    assert actual == expected, f"{name}: expected {expected}, got {actual}"
    print(f"{name}=={actual}")
agent = create_agent(ScriptedChatModel(responses=[AIMessage(content="environment OK")]), tools=[])
assert agent.invoke({"messages": [{"role": "user", "content": "check"}]})["messages"][-1].content == "environment OK"
print("PASS: imports + a real agent graph invocation")

版本不符时应先比较预期和实际环境，再在独立虚拟环境重建锁文件基线。不要在缺少诊断时反复执行“升级所有包”，那会让错误更难复现。

04真实踩坑：pip check 通过，导入仍失败

本教程制作时遇到一组具体问题：langgraph==1.0.5 与 langgraph-prebuilt==1.0.10 的依赖元数据检查可以通过，但实际导入出现与 ExecutionInfo 相关的 ImportError。最终将 prebuilt 固定为 1.0.5，并重新运行 Agent 示例确认恢复。

原因在于 pip check 主要检查已声明的包版本约束，不能证明包之间所有实际符号都兼容。完整验证至少包括：依赖解析通过、关键模块可导入、代表性功能可运行。当前基线已把两者锁为 1.0.5；完整的间接依赖见 requirements.lock.txt。

另一个可复现的环境差异是 Windows 受限沙箱：本次验证中，连最小 asyncio.run 都可能在创建本地 socketpair 时等待，沙箱外同一示例正常完成。因此异步挂起时应先用最小 asyncio 程序判断是运行环境问题还是业务逻辑问题，不要直接删掉异步实现。

05最新官方文档也需要版本判断

官方在线文档会持续更新。核对时，流式页面已推荐 1.3 引入的 event streaming，并展示 stream_events(..., version='v3')。这不是本教程 1.2.0 的 API，不能因为它来自官方页面就直接复制进锁定环境。

本教程使用 1.2.0 环境里实际运行的 stream、astream 及对应 stream_mode。阅读文档时同时检查引入版本、已安装源码、函数签名和最小验证。升级教程时要一起更新代码、锁文件、内容、测试结果与交接文件，不能只把页脚的版本数字改大。

06排错练习与验收

  1. 入门：运行环境检查并保存输出。验收条件：精确版本符合 EXPECTED，末行显示真实 Agent 调用通过。
  2. 进阶：找一段旧 LLMChain 示例，只迁移“提示 → 模型 → 文本解析”，用固定输入比较返回类型和内容。验收条件：明确列出需要同步修改的下游取值代码。
  3. 挑战：为一个旧记忆流程写迁移验收清单：同线程延续、不同线程隔离、不同租户隔离、重启恢复、工具调用消息配对。先在纸面说明预期，再运行对应示例；不要为了演示依赖冲突破坏现有环境。
