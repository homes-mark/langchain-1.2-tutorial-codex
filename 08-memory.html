011. 先回答：究竟是谁记住了什么？

模型请求本身通常不会自动继承你上一次的输入。应用把过去的消息重新放入本次上下文，模型才有机会利用它。Memory 因而包含两个独立问题：哪些信息被保存，哪些信息本轮被发送给模型。数据库中保存一万条消息，不意味着应该把一万条都塞进提示词。

LangChain 1.2 的 Agent 以状态保存消息，checkpointer 为会话保存执行状态；调用时用 thread_id 选择会话。跨会话的用户偏好则适合放进 Store。相关 API 的作用域见官方短期记忆说明及长期记忆说明。

信息示例本章载体作用域
会话状态刚刚询问的报销单号messages + checkpointer某个 thread
长期偏好用户希望中文简短回答Store namespace + key同一用户多个 thread
可信身份登录用户与租户应用鉴权与运行上下文本次请求
企业知识最新差旅制度带版本和权限的检索库授权文档集合

这些数据可以在一次回答中组合，但生命周期不同。尤其不要把“用户声称自己是管理员”的聊天内容升级成可信身份。

022. 可运行：两条会话与一份偏好

依赖基线：langchain==1.2.0、langchain-core==1.2.5、langgraph==1.0.5，完整环境以 requirements.lock.txt 为准。从教程根目录运行 python examples/08_memory.py。

examples/08_memory.py下载源文件 ↗
"""依赖：langchain==1.2.0 / langgraph==1.0.5；完整版本见 requirements.lock.txt。
运行：python examples/08_memory.py；无需网络或 API 密钥。
"""

from langchain.agents import create_agent
from langchain_core.messages import AIMessage, HumanMessage
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.store.memory import InMemoryStore

from common import ScriptedChatModel


def main() -> None:
    saver = InMemorySaver()
    store = InMemoryStore()
    # namespace 由可信应用上下文构造，不能相信用户在聊天中声明的身份。
    namespace = ("acme", "users", "u-001", "preferences")
    store.put(namespace, "reply_style", {"language": "zh", "concise": True})
    model = ScriptedChatModel(responses=[
        AIMessage(content="已收到你的姓名。"),
        AIMessage(content="你叫小林。"),
        AIMessage(content="这个新会话还没有你的姓名。"),
    ])
    agent = create_agent(model=model, tools=[], checkpointer=saver, store=store)
    config_a = {"configurable": {"thread_id": "acme:u-001:session-a"}}
    config_b = {"configurable": {"thread_id": "acme:u-001:session-b"}}
    agent.invoke({"messages": [{"role": "user", "content": "我叫小林"}]}, config_a)
    result = agent.invoke({"messages": [{"role": "user", "content": "我叫什么？"}]}, config_a)
    other = agent.invoke({"messages": [{"role": "user", "content": "我叫什么？"}]}, config_b)

    saved = agent.get_state(config_a).values["messages"]
    assert len(saved) == 4
    assert any(isinstance(msg, HumanMessage) and "小林" in msg.content for msg in saved)
    assert len(other["messages"]) == 2
    assert all("我叫小林" != msg.content for msg in other["messages"])
    profile = store.get(namespace, "reply_style")
    assert profile is not None and profile.value["language"] == "zh"
    assert store.get(("beta", "users", "u-001", "preferences"), "reply_style") is None
    print(result["messages"][-1].content)
    print(f"同一会话消息数：{len(saved)}；新会话消息数：{len(other['messages'])}")
    print("跨会话偏好可读；另一租户命名空间没有该记录：PASS")
    print("注意：模型回复预设；断言验证状态持久化与隔离，不证明模型记忆推理能力。")


if __name__ == "__main__":
    main()

预期包含：同一会话消息数：4；新会话消息数：2 和 PASS。回复“小林”由测试模型预设；真正值得观察的是返回状态和 get_state 中保存的消息。断言直接验证旧消息存在于 session-a、没有进入 session-b，避免把一次碰巧正确的文字回复当成记忆功能已经可靠。

033. 顺着数据流读代码

  1. 先创建一个 saver，并让多次调用共享它。若每次请求都创建新的内存 saver，上一次状态就无法找到。
  2. 第一次只提交新增的用户消息；Agent 生成回复后，这条会话共有两条消息。
  3. 第二次使用同一 config，再提交新增消息。checkpointer 读回历史，最终共有四条消息。不要每次再提交完整历史，否则可能重复追加。
  4. 换一个 thread_id 后，没有旧会话消息。相同 user_id 并不会自动合并会话。
  5. 偏好以固定 namespace 和 key 写入 Store；另一条会话只要经鉴权属于同一用户，就可以读取同一记录。该示例直接展示 Store 的读写，尚未把偏好注入模型提示。

acme:u-001:session-a 仅用于让例子容易辨认。生产端可用不可预测的会话 ID，并在数据库中验证其所有者。知道别人的 thread_id 绝不能等于获得访问权限；命名规范也不能代替授权检查。

044. 历史越来越长时怎么办

先制定消息预算，再选择保留策略。近期消息保留原文，旧消息可摘要，稳定偏好单独存储，业务事实查询权威系统。摘要可能遗漏否定条件、日期与金额，应让重要事实带来源与更新时间，允许用户修正。不要把模型猜测直接写成永久档案。

裁剪消息时必须保持工具协议完整：一个 AI 工具请求与对应的 ToolMessage 需要正确配对。只按列表长度机械截断可能留下孤立的工具结果，导致模型提供方报错。若采用内置摘要中间件，额外的摘要模型调用也计入延迟和费用；应在固定测试集上检查丢失信息的比例。

删除长期偏好不会自动删除历史消息中的同一信息。实现删除需求时，需要同时覆盖 Store、checkpoints、日志、缓存和向量索引。保留期限、导出能力和备份恢复应成为数据设计的一部分。

055. 三档练习与验收

  1. 入门：为 session-a 再增加一轮输入，并为脚本模型增加一条回复。验收：会话消息数从 4 增到 6；session-b 仍为 2。
  2. 进阶：给同一租户新增用户 u-002，保存不同的 language。验收：两个用户读取自己的 namespace 得到不同值；读取不存在的 key 返回空。主动尝试用 u-001 的身份读取 u-002 数据，并在应用入口拒绝它。
  3. 高级：将“读取已确认偏好”做成只读工具，通过 ToolRuntime 获取应用传入的身份。验收：模型可见 schema 不包含 tenant_id/user_id；两个 thread 读取同一偏好；新租户拿不到已有偏好。可参考 11 章的可信上下文模式。

增加真实模型实验时，输入“我叫小林”再询问姓名，同时检查消息状态和真实回答。把“模型回答正确率”与“状态保存正确率”分别记录，才能定位失败发生在模型还是应用。

066. 常见误区与升级路线

InMemory 不等于持久数据库。

本章两个后端都存在当前 Python 进程的内存中，关闭进程数据即丢失。它们演示 API 和作用域，不提供重启恢复、跨进程共享或生产级并发保证。

不要在新项目里照搬旧版 ConversationBufferMemory 教程作为 1.2 Agent 的默认方案；本教程采用状态与 checkpointer。数据库后端通常需要单独的集成包、连接管理和初始化步骤，不能仅替换一个类名就宣布上线。还要检查同一会话并发写入、租户绑定、保留策略及备份恢复。

记忆保存过去的互动；RAG 引入外部知识。下一章从 文档索引 开始，让 Agent 回答有据可查的企业制度，而不是把整个知识库装进聊天历史。
